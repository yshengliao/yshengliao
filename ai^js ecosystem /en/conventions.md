# ai*js — conventions

The contract every `ai*js` package follows. Use this as the checklist when starting a new sibling.

> 繁體中文 → [../zh/conventions.md](../zh/conventions.md) ｜ Back to [index](../README.md)

## Naming contract

| Surface | Convention | Rationale |
|---|---|---|
| Factory | `createX(opts?)`, never a `class` constructor | Functional surface; easy to pass around, mock, and tree-shake. |
| Disposal | `dispose()` — **idempotent**; after dispose all public methods throw `XDisposedError` synchronously | Consistent teardown across the family. |
| Reset | `reset()` — wipe to initial state without releasing internal buffers | HMR-friendly; a distinct concept from dispose. |
| Subscription | `on(event, handler, opts?: { signal?, once? }) => () => void` | Returns an unsubscribe function; honours `AbortSignal`. |
| Long-running / async | `(args, { signal?: AbortSignal })` | Every long-lived operation accepts a signal. |
| Domain neutrality | No domain nouns (`player`, `level`, `score`, `sprite`, `collision`, …) in source or public API | Application terminology belongs in usage examples, never in the API surface. |

## `package.json` shape

```jsonc
{
  "name": "aiXXXjs",
  "version": "0.5.0",
  "type": "module",
  "sideEffects": false,
  "main": "./dist/index.cjs",
  "module": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "exports": {
    ".":         { "types": "./dist/index.d.ts",   "import": "./dist/index.js",   "require": "./dist/index.cjs"   },
    "./feature": { "types": "./dist/feature.d.ts", "import": "./dist/feature.js", "require": "./dist/feature.cjs" }
  },
  "files": ["dist", "README.md", "README_ZHTW.md", "LICENSE", "llms.txt", "llms-full.txt"],
  "engines": { "node": ">=18.0.0" },
  "license": "MIT"
}
```

- Dual ESM + CJS output via `tsup`.
- `sideEffects: false` so bundlers can drop unused subpaths.
- One subpath export per optional capability; the root keeps the stable core.
- **Zero `dependencies`.** Runtime is zero-dep. The only allowed exception is an *optional* `peerDependency` (e.g. `fast-check` for the PBT adapter, `howler` for the audio shell). Anything heavier belongs in user-land.
- **No cross-package imports.** `aiXXXjs` must not `import 'aiYYYjs'`. Integration is a documentation concern, not a dependency.
- `aiecsjs` additionally ships `api.json` in `files[]` (a machine-readable export manifest).

## Documentation contract (AI-readable)

Every package ships:

| File | Purpose |
|---|---|
| `README.md` (English, canonical) | Quick start, mental model, API reference, FAQ. |
| `README_ZHTW.md` | Traditional-Chinese mirror. |
| `CHANGELOG.md` | Keep-a-Changelog + SemVer. |
| `STABILITY.md` | Per-export stability tag + `since` version. |
| `llms.txt` | [llmstxt.org](https://llmstxt.org/) discovery index. |
| `llms-full.txt` | Single-file complete API reference for LLM consumption. Generated by `scripts/build-llms-full.mjs`. |
| `api.json` | Machine-readable export manifest (where provided). |
| `CONTRIBUTING.md` | What gets in easily, what needs discussion. |
| `LICENSE` | MIT. |

Stability tags use one vocabulary across the family: **stable**, **experimental**, **internal**, **deprecated**. Same tag, same expectation everywhere.

## CI & quality gates

`prepublishOnly` runs in this order:

```
typecheck → lint → coverage → build → verify:exports → check:size
```

| Gate | Tool | Threshold |
|---|---|---|
| Typecheck | `tsc --noEmit` with `strict + noUncheckedIndexedAccess + exactOptionalPropertyTypes` | Zero errors. |
| Lint | [Biome](https://biomejs.dev/) | Zero errors. |
| Tests | Vitest behavioural tests | ≥95% statements / lines / functions, ≥90% branches (some packages enforce 100). |
| Build | `tsup` dual ESM/CJS + `.d.ts` | — |
| Exports | `scripts/verify-exports.mjs` | Every `exports` entry maps to an existing `dist/` file. |
| Size | `scripts/check-size.mjs` | Per-subpath gzip budget; a failure blocks publish. |

## Package skeleton

```
aiXXXjs/
├── src/
│   ├── index.ts              # root re-exports
│   └── <feature>/index.ts    # subpath entries
├── test/                     # vitest behavioural tests
├── examples/<NN>-<scenario>/ # executable demos
├── scripts/
│   ├── verify-exports.mjs    # gate: exports vs dist/
│   ├── check-size.mjs        # gate: per-subpath gzip budget
│   └── build-llms-full.mjs   # generator: README + src → llms-full.txt
├── README.md / README_ZHTW.md
├── CHANGELOG.md
├── STABILITY.md
├── CONTRIBUTING.md
├── llms.txt / llms-full.txt
├── biome.json
├── tsup.config.ts
├── tsconfig.json
├── vitest.config.ts
├── LICENSE
└── package.json
```

`aifsmjs` is the most-conformant member — use its repository as the reference when starting a new package.

## Composition (by convention, not dependency)

The packages address orthogonal concerns and **do not depend on each other**. Compose them by passing plain data across boundaries:

- A state machine owns high-level flow state; an ECS world owns per-tick entity data. The machine signals a transition → the application spawns or updates entities; the ECS signals a condition → the application feeds an event back to the machine.
- Stream an ECS snapshot to a sandboxed context (iframe / worker) through the bridge — serialise to plain JSON first; the envelope drops `Date`, `Map`, `Set`, and class prototypes.
- The bridge is the side-effect channel to a host (parent frame, WebView, worker); the emitter is the in-process fan-out.

None of these compositions add a `dependencies` entry — every package stays independently publishable.
